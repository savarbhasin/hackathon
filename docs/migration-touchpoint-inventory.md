## Execution engine (`src/lib/engine.ts`)

### Column mapping
`Column = backlog | working | blocked | approval | settled` (line 7). Pump transitions (307–321):
- `turn.created` → persist turnId
- `tool.approval_required` → `approval`
- `tool.response_required` / `mcp.auth_required` → `blocked`
- `turn.done` → `handleDone` (334–440)
- stream error → `blocked` (323–331)

`handleDone` branches: clean done → settle (prefer mark_done output over turn output ≤8000 chars) + **sweep()**; cancelled → reset to `backlog`, wipe session/turn/pendingActions/handoff/output (redispatch-safe); error → `blocked`; otherwise pause → enrich requiredActions from merged events, persist `pendingActions` JSON, set column `approval`/`blocked`.

### Key functions
- `buildKickoff` (46–126): MISSION/goal, assignment, `TASK_ID:` embed (69), predecessor summaries ≤1200 chars + settled-only handoff docs, successor block requiring `kind="handoff"` docs, "call mark_done exactly once" rule.
- `dispatchTask` (166–242): guards (backlog, sessionId==null), conditional-updateMany claim, session create `{agent:{name:role}}`, persist sessionId, append activity.started, then **fire-and-forget `void runPump(...)` at line 210**. Failure path recovers claim conditionally, deletes remote session (274–280).
- `runPump` (282–332): opens `createTurnStream`, iterates `withMetadata()`, tracks `providerStreamId` (288–290, logged but never used to resume), merges deltas into in-memory Map keyed by event id, appends first-sight events via `appendTaskEvent`. All pump state is process-local memory; loop runs up to SDK timeout 900s (`tf.ts:9`).
- `sweep()` (442–458): ready = zero deps OR all deps settled within same mission; sequential dispatch. Invoked from handleDone and MCP `dispatch_ready`. Note: auto-dispatches any dep-less backlog task despite comment intent.
- `resolvePause` (460–507): builds resume inputs (`user.tool_approval` / `user.tool_response` items), clears pendingActions, column → working, **fire-and-forget `void runPumpResume(...)` at line 505** (new turn, same session).
- `retryTask` (244–272): blocked only; refuses if pending question or connector-auth; resets to backlog, deletes remote session, fresh dispatch.

## Orchestrator (`src/lib/orchestrator.ts`, `/api/chat/route.ts`)

- Per-conversation TrueForge session persisted on `Conversation.sessionId` (unique); health-check + recreate on reuse (53–62); spec refreshed each turn via `sessions.update` (64–70).
- Setting-table automation session: key **`orchestrator_automation_session_id`** (`orchestratorSay`, 499–529). Note: differs from AGENTS.md's `orchestrator_session_id`.
- `runOrchestratorTurn` (114–188): async generator of ChatEvents; **in-memory promise-chain mutex** (`conversation-turn-lock.ts`) — process-local serialization to replace with queue-level concurrency.
- `resumeOrchestratorTurn` (208–300): finds latest message with `pauseActions`, validates selectors (`orchestrator-pause.ts:31-92`), streams resume turn, requires `providerCompleted` else keeps pause intact.
- `streamSessionTurn` (302–383): same delta-merge pattern; emits `delta`/`tool`/`status`/`pause` ChatEvents; extracts enriched PersistedPauseActions with selector UUIDs (442–483); metrics on done (373–377).
- `/api/chat/route.ts`: `maxDuration = 800`; abort plumbing forwards client disconnect as `"client_disconnected"`; manual SSE framing + `[DONE]`.

## TrueForge SDK integration

- Client singleton `tf.ts`: `new TrueForge({ baseUrl: TRUEFORGE_BASE_URL ?? :8790, timeoutInSeconds: 900 })`.
- Used APIs: sessions create/get/update/delete, `createTurnStream(...).withMetadata()` (engine 285–288 — no abort signal passed), agents CRUD (seeding/reconciliation 310–351), mcpServers/models/capabilities probes.
- Delta merging confirmed in both engine and orchestrator (`isEventDelta`/`mergeEventDelta`); camelCase dual-reads (`requiredActions ?? required_actions`).
- Approval pauses: Task.pendingActions array `{type, threadId, calls:[{id, threadId, name, args}]}` (approve/answer source of truth); ChatMessage.pauseActions `{selector uuid, type, threadId, toolCallId, name, question, options, argsPreview}`.
- **Cursor/sequence checkpointing does not exist**: `Task.lastSeq` is a local log sequence, not a provider cursor; a crashed pump loses the stream (recovery = manual retry or pause/resume path). Migration must add provider-seq checkpointing — see companion SDK research for `subscribeToTurn(afterSequenceNumber)`.

## Cross-cutting risk summary (what breaks first)

1. Four pools of process-local state: pump loops + delta maps, per-task event-write queues, conversation turn locks, SerialTaskQueue + croner jobs Map. All assume a resident process.
2. MCP handlers execute engine logic in-process → must become queue enqueues.
3. No provider-side checkpointing for interrupted pumps → worker needs resumable subscribe + lastProcessedSeq tracking (GO per SDK research, pending live verification).
4. The only realtime surface is board SSE backed by a 1 Hz poll — direct Convex-subscription replacement.
